データは、データベース → テーブル → ボクセルの 3 段で管理します。テーブルは空間ID をキーにした 1 つの値の集まりで、1 つのボクセルが持てる値は 1 つです。

```text
Kasane サーバー
└ データベース（例：city）
   ├ テーブル（例：building。値の型は TEXT）
   │  ├ 20/0/931389/412900 → "東京駅"
   │  └ 20/0/931390/412900 → "丸の内ビル"
   └ テーブル（例：risk。値の型は INT）
      └ 20/0/931389/412900 → 80
```

## テーブルの設定

| 項目 | 内容 | 作成後の変更 |
| --- | --- | --- |
| 名前 | データベース内で一意 | できる |
| 値の型 | 下の 5 つのどれか | できない |
| 最大ズームレベル | 書き込める ID の細かさの上限（25 で約 1 m） | できない |
| 時間を扱うか | 時空間ID を書き込めるか | できない |
| 制約 | 値の範囲や選択肢（任意） | できる |

| 型 | 値 | 例 |
| --- | --- | --- |
| TEXT | 文字列 | 建物の名前 |
| INT | 整数 | 危険度、人数 |
| BOOLEAN | 真偽値 | 通行できるか |
| ENUM | 決めておいた選択肢のどれか | 天気（晴れ・曇り・雨） |
| PRESENCE | 値なし（存在だけを記録する） | 建物がある場所 |

小数の型はありません。10 倍や 100 倍した整数で INT に入れます。

## ユーザーと権限

ユーザー名とパスワードでログインします。権限は「範囲」と「役割」の組み合わせです。

| 範囲 | 対象 |
| --- | --- |
| global | サーバー全体 |
| database | 1 つのデータベースと、その中の全テーブル |
| table | 1 つのテーブル |

| 役割 | できること（下の役割は上の役割を含む） |
| --- | --- |
| read | 検索、クエリ、テーブル情報の取得 |
| write | 書き込み、削除 |
| manage | テーブルの作成・削除・改名・コピー |
| admin | ユーザーの管理、権限の付与（global のみ） |

たとえば「city への write」を持つユーザーは、city のどのテーブルにも読み書きできますが、テーブルは作れません。権限が無いと `permission_denied` になります。
