Kasane のデータは、データベース・テーブル・ボクセルの 3 段の入れ物に入っています。

```text
Kasane サーバー
└ データベース（例：city）
   ├ テーブル（例：building。値の型は TEXT）
   │  ├ 20/0/931389/412900 → "東京駅"
   │  └ 20/0/931390/412900 → "丸の内ビル"
   └ テーブル（例：risk。値の型は INT）
      └ 20/0/931389/412900 → 80
```

- **データベース**：テーブルをまとめる入れ物です。用途やプロジェクトごとに分けます。
- **テーブル**：1 種類の情報（建物の名前、危険度、天気など）を入れる場所です。
- **ボクセル**：テーブルの中では、空間ID（[時空間ID の基礎](/concepts/spatial-id/)）ごとに値を 1 つ持ちます。同じボクセルに 2 つの値は入りません。

表計算ソフトにたとえると、データベースがファイル、テーブルがシート、空間ID が行の見出し、値がセルの中身です。

## テーブルを作るときに決めること

| 項目 | 内容 | あとから変更 |
| --- | --- | --- |
| 名前 | データベースの中で重ならない名前 | できる |
| 値の型 | 下の表の 5 つから 1 つ | できない |
| 最大ズームレベル | 書き込める ID の細かさの上限（25 なら約 1 m） | できない |
| 時間を扱うか | 時空間ID（時間つきの ID）を書けるようにするか | できない |
| 制約 | 値の範囲や選択肢（省略できる） | できる |

値の型は次の 5 つです。

| 型 | 入れる値 | 例 |
| --- | --- | --- |
| TEXT | 文字列 | 建物の名前 |
| INT | 整数 | 危険度、人数 |
| BOOLEAN | `true` / `false` | 通行できるか |
| ENUM | 決めておいた選択肢のどれか | 天気（晴れ・曇り・雨） |
| PRESENCE | 値なし（「ある」ことだけを記録する） | 建物がある場所 |

小数の型はありません。小数を扱うときは、10 倍や 100 倍した整数にして INT に入れます。

## ユーザーと権限

Kasane を使うには、ユーザー名とパスワードでログインします。ユーザーには「どこに対して、何ができるか」を組み合わせた権限が付いています。

どこに対して：

| 範囲 | 内容 |
| --- | --- |
| global | サーバー全体 |
| database | 1 つのデータベースと、その中のテーブルすべて |
| table | 1 つのテーブルだけ |

何ができるか（下の役割は、上の役割の操作をすべて含みます）：

| 役割 | できること |
| --- | --- |
| read | 検索、クエリ、テーブルの情報を見る |
| write | 書き込み、削除（`insert`・`upsert`・`remove`） |
| manage | テーブルの作成・削除・改名・コピー |
| admin | ユーザーの作成・削除、権限の付与（global にだけ付けられる） |

たとえば「データベース city への write」を持つユーザーは、city の中のどのテーブルにも読み書きできますが、テーブルを作ることはできません。権限の無い操作をすると `permission_denied` のエラーになります。

クライアントでの操作は、ガイドの[データベースとテーブル](/guide/databases/)で説明しています。

## まとめ

- データはデータベース → テーブル → ボクセルの 3 段に入る。1 つのボクセルには値が 1 つ
- テーブルの値の型・最大ズームレベル・時間を扱うかは、作るときに決めて、あとから変えられない
- 権限は「どこに（global / database / table）」と「何ができるか（read / write / manage / admin）」の組み合わせ
