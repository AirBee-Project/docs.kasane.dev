データは、データベース → テーブル → 時空間IDの 3 段で管理します。テーブルは[時空間ID](/concepts/spatial-id/#時空間id) をキーにした値の集まりで、テーブル内の 1 つの時空間IDが持てる値は 1 つのみです。

```text
Kasane サーバー
└ データベース（例：city）
   ├ テーブル（例：building。TEXT型）
   │  ├ 20/0/931389/412900 → "東京駅"
   │  └ 20/0/931390/412900 → "丸の内ビル"
   └ テーブル（例：risk。INT型）
      └ 20/0/931389/412900 → 80
```

## テーブルの設定

| 項目 | 内容 | 作成後の変更 |
| --- | --- | --- |
| `name` | テーブル名 | ○ |
| `data_type` | 値の型。下の 5 つのどれか | × |
| `max_zoom_level` | 書き込める空間ID の細かさ（[ズームレベル](/concepts/spatial-id/#ズームレベルと親子関係)）の上限 | × |
| `is_temporal` | 時空間ID を書き込めるか | `false` → `true` のみ ○ |
| `value_index` | 値による絞り込み用の索引を持つか | × |
| `constraints` | 値の範囲や選択肢（任意） | ○ |
| `description` | 説明文（任意） | ○ |

### 値の型

| 型 | 値 | 例 |
| --- | --- | --- |
| TEXT | 文字列 | 建物の名前（例: "東京駅"） |
| INT | 整数 | 危険度、人数 （例: 80） |
| BOOLEAN | 真偽値 | 通行できるか （例: true） |
| ENUM | 決められた選択肢 | 天気（例: 晴れ・曇り・雨） |
| PRESENCE | 値なし（存在だけを記録） | 建物がある場所 |


## ユーザーと権限

ユーザー名とパスワードでログインします。権限は「範囲」と「役割」の組み合わせです。

### 範囲

| 範囲 | 対象 |
| --- | --- |
| global | サーバー全体 |
| database | 1 つのデータベースと、その中の全テーブル |
| table | 1 つのテーブル |

### 役割

| 役割 | できること（下の役割は上の役割を含む） |
| --- | --- |
| read | 検索、[クエリ](/concepts/query/)、[テーブル情報](#テーブルの設定)の取得 |
| write | 書き込み、削除（`Insert`・`Upsert`・`Remove`） |
| manage | テーブルの作成・削除・改名・コピー |
| admin | ユーザーの管理、権限の付与（global のみ） |

たとえば「city への write」を持つユーザーは、city のどのテーブルにも読み書きできますが、テーブルは作れません。権限が無いと `permission_denied` になります。
