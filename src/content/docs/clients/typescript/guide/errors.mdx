## 2 種類のエラー

| エラー | いつ起きるか | 見分け方 |
| --- | --- | --- |
| サーバーのエラー（`ConnectError`） | サーバーがリクエストを断ったとき。権限が無い、テーブルが無い、型が違うなど | `isKasaneError(e)` |
| `SpatialIdError` | 空間ID を作るときに、値が範囲外だったり書式が違ったりしたとき。通信する前にクライアントが投げる | `e instanceof SpatialIdError` |

## サーバーのエラー

`e.message` の先頭の `[ ]` に、エラーの種類が入っています。

| 種類 | よくある原因 | 判定する関数 |
| --- | --- | --- |
| `invalid_argument` | 型違い、制約違反、ズームレベルの上限超え、使えない時間間隔、`policy` の指定漏れ | — |
| `not_found` | テーブルが無い | `isNotFoundError(e)` |
| `already_exists` | 同じ名前のテーブルがある | `isAlreadyExistsError(e)` |
| `permission_denied` | 権限が無い | `isPermissionDeniedError(e)` |
| `unauthenticated` | 認証できない（トークンが無効など） | `isUnauthenticatedError(e)` |
| `unknown` | サーバーにつながらない（URL の誤り、サーバーの停止など）。メッセージは `fetch failed` や `Unable to connect` | — |
| `internal` | サーバー内部のエラー。Kasane の不具合の可能性がある | — |

`isKasaneError(e)` は TypeScript の型ガードなので、`if (isKasaneError(e))` の中では `e.message` などをそのまま使えます。

ログインのときにユーザー名やパスワードが間違っていると、v0.0.3 ではエラーにならず、`connect` が終わりません（[接続と認証](/clients/typescript/guide/connect/)）。

## SpatialIdError

`e.info.kind` に、何が不正だったかが入っています。

| kind | 内容 |
| --- | --- |
| `ZOutOfRange` | ズームレベルが範囲外 |
| `FOutOfRange` / `XOutOfRange` / `YOutOfRange` | 各インデックスがそのズームレベルの範囲外 |
| `TOutOfRange` / `TIntervalError` | 時間インデックスや時間間隔が不正 |
| `ParseSpatialIdFormat` | `parse` に渡した文字列の書式が違う |

## まとめ

- サーバーのエラーは `isKasaneError(e)` で見分け、`e.message` の `[種類]` で原因が分かる
- 空間ID の値の誤りは、通信する前に `SpatialIdError` になる
