---
title: 自分のデータを使う
---


このページでは、自分のデータを Kasane で使うための準備をまとめています。テスターの皆さんにいちばんお願いしたいのは、自分のデータを負荷試験ツール（準備中）に読み込ませて、ベンチマークを取っていただくことです。開発チームが用意できないデータで測ることで、思わぬ不具合や遅い操作が見つかります。気づいたことは、その都度 [Issue](/tutorial/next/) で送ってもらえると助かります。

負荷試験ツールは、時空間ID と値を並べたファイル（Nazori の TXT、AirBee の時空間 JSON、ID と値の CSV）を読み込めるようにする予定です。地図データは、下の方法で先に時空間ID に変換しておいてください。

## 試してみてほしいこと

- 自分の仕事や研究のデータを、Kasane に入れるとしたらどう表すか考えて、実際に入れてみる
- 複数のテーブルを作り、クエリで重ね合わせてみる（例：建物の周りに `falloff` で緩衝帯を作る）
- 時間を扱うテーブルで、時間ごとに変わるデータを入れて検索してみる
- 使っていて分かりにくかった API 名やエラーメッセージ、足りないと感じた機能を書き留めておく

## AirBee が目指すものと、役立つデータ

AirBee は、ドローンが安全に飛べる経路を決めるための「リスクマップ」を、時空間ID で作ることを目指しています。リスクマップは、次のようなデータをボクセルごとに重ね合わせて作ります。実データで試すときの参考にしてください。

| データ | 例 | テーブルの型の例 |
| --- | --- | --- |
| 建物・構造物 | 建物がある場所、高さ | `presence` |
| 道路・鉄道 | 道路の上空など、避けたい場所 | `presence` |
| 地形 | 標高（地面より下は飛べない） | `int` |
| 飛行が制限される区域 | 空港周辺、人口が集中する地区 | `presence` / `enum` |
| 時間で変わる情報 | 天気、風、人の多さ | 時間を扱うテーブル（`int` / `enum`） |

Kasane が受け付けるのは時空間ID と値だけなので、地図データは先に時空間ID に変換してから書き込みます。建物・道路・地形などの公開データを変換して、共有データベース `shared` に入れておく準備を進めています（準備中）。

## 実際の都市データを使う

[Nazori](https://airbee-project.github.io/Nazori/) を使うと、国土交通省の [PLATEAU](https://www.mlit.go.jp/plateau/) が公開している建物・道路のデータ（CityGML）を空間ID に変換できます。ブラウザの中で動くので、インストールは要りません。

1. [G空間情報センター](https://www.geospatial.jp/ckan/dataset/plateau)から、好きな都市の CityGML をダウンロードします。建物は `udx/bldg/`、道路は `udx/tran/` にあります。まずは 1〜数ファイルで試すのがおすすめです。
2. Nazori で、対象（建築物か道路）、変換方式 `Flat`、出力 `TXT`、ズームレベル（23〜25 くらい）を選んで変換します。
3. ダウンロードされた TXT を、負荷試験ツールにそのまま読み込ませます（ツールは準備中です）。

Nazori が対応しているのは、今のところ PLATEAU の建物と道路だけです。PLATEAU のデータを使った結果を公開するときは、PLATEAU の利用規約に従って出典を書いてください。

## 準備中のもの

- 運営が用意する共有データ（`shared` データベース）。建物のリスク値や、規模の違う都市データを、正解の件数つきで用意する予定です。
- 大量のデータで整合性と性能を検証する負荷試験ツール。
