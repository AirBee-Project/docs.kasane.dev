## ステップ 7：値の型と制約

TEXT・INT・BOOLEAN・ENUM・PRESENCE の 5 つの型で、書いた値が返ること、型違いや制約違反が断られることを確かめます。

<Code code={s7} lang="ts" title="07-types.ts" />

<TutorialRunner step="07-types" />

実行結果の例：

```text
OK  TEXT: 文字列が返る
OK  TEXT に数値を書くとエラー
    [invalid_argument] Value type mismatch: expected String, got Int
OK  BOOLEAN: true が返る
OK  PRESENCE: 1 件あり、値は null
OK  INT: 80n が返る
OK  INT の制約（最大 100）を超えるとエラー
    [invalid_argument] Constraint violation: Value 150 is greater than maximum 100
OK  ENUM: 晴れ が返る
OK  ENUM の選択肢に無い値はエラー
    [invalid_argument] Constraint violation: Value '雪' is not among allowed choices: ["晴れ", "曇り", "雨"]
```

PRESENCE は「そこに何かがある」ことだけを記録する型で、値は `null` です。小数の型は無く、INT に `3.9` を渡すとクライアント側で `3` に切り捨てられます。制約の指定に `as never` が付いているのは、v0.0.3 のクライアントの型の都合です。

```text
書き込んだ ID: 20/0/931389/412900_3600/489768 20/0/931389/412900_3600/489769
OK  00:00〜01:00 は 晴れ だけ
OK  00:00〜02:00 は 2 件
OK  その日全体で検索すると 2 件
OK  全時間の値は、どの時刻で検索しても返る
OK  1800 秒の時間間隔はエラー
    [invalid_argument] Invalid spatial ID: interval 1800 is not allowed; i must be one of: 34359738368, 86400, 3600, 60, 1
OK  時間を扱わないテーブルに時間つき ID を書くとエラー
    [invalid_argument] Invalid spatial ID: This table does not accept time-indexed spatial IDs for write operations
weather の全データ: [ '20/0/931389/412900_3600/489768 => 晴れ', '20/0/931389/412900_3600/489769 => 雨', '20/0/931390/412900 => 常に存在' ]
```

- 使える時間間隔は 1 秒・60 秒・3600 秒・86400 秒の 4 つだけです。
- 時間を扱うテーブルに時間なしの ID で書くと、全時間の値になります。
- 検索は、指定した時間と重なるデータを返します。
